# src/bun/index.ts

- Loads account storage (see `account-storage.md`) with top-level `await` before the menu and window are created, so every handler and the task queue see the stored accounts. A broken `accounts.json` stops the start and is left untouched.
- Answers the webview's requests (see `rpc-interface.md`). Every request whose params come from the webview is checked first with `parseTaskRequest` or the parsers in `account-request-parser.ts`, so a malformed request rejects the webview's call.
- `findAccount` gives the task queue and the browse sessions the stored account, secrets included; the webview only ever receives `AccountSummary` values.
- The document requests (`listCollections` … `deleteDocument`) are checked with `browse-request-parser.ts` and run in the database's browse session (`browse-sessions.md`). Removing an account also closes its browse sessions, and the `before-quit` event closes them all.
- `importServiceAccount` shows the native open dialog for one `.json` file and reads it with `readServiceAccountKey` (16 KB limit, checked before reading).
- `signInWithGoogle` uses the active OAuth client (`AccountStorage.getOAuthClient`: the user's saved client, else the built-in one, else it fails with "Save your OAuth client…") and stores the signed-in user with that client's source and id, because Google refreshes a token only with the client that issued it. Signing in again with an email that is already added replaces that account's token and client (same account id, `addGoogleUser`) and closes its browse sessions.
- `BUILT_IN_OAUTH_CLIENT` is a global the bundler replaces with the client from `google-oauth-client.local.json`, or `null` (`electrobun-config.md`). Only this file reads it; it is passed to account storage and never sent to the webview. `getOAuthClient`, `setOAuthClient` and `removeOAuthClient` answer `OAuthClientSettings`, which holds no secret.
- The worker path comes from `PATHS.RESOURCES_FOLDER`; see `electrobun-config.md`.
- Loads the app state (`app-state-storage.md`) before the window is created. A saved window frame is applied with `setFrame` on a hidden window that is then shown: the constructor's `frame` sets the content size, while `getFrame`/`setFrame` use the outer frame (title bar included), so passing the saved frame to the constructor would grow the window by the title bar height on every start. A saved frame that is on no display (`Screen.getAllDisplays`) keeps only its size and is centered. Fullscreen and minimized frames are not saved; `resize` and `move` events save the frame (debounced).
- `getViewState` answers the webview's saved view state; the `saveViewState` message (webview → main) is checked with `parseViewState` and saved; an invalid one is logged and dropped. `before-quit` flushes a pending save.
- Menus: View → Command Palette… (Cmd+K); Tab → New Tab (Cmd+T), Close Tab (Cmd+W), Show Previous Tab (Cmd+Shift+[), Show Next Tab (Cmd+Shift+]). Their `action` is one of `MENU_ACTIONS`; `application-menu-clicked` forwards a known action as the `menuActionInvoked` message. Accelerators are Electron-style strings that Electrobun parses into an `NSMenuItem` key equivalent and modifier mask, so they work while the webview has focus and fire once.
- `startLive` / `stopLive` are checked with `parseLiveQueryParams` / `parseStopLiveParams` and run in the browse session; each listener update is forwarded as the `liveUpdated` message (`browse-sessions.md`).
- The `new-window-open` webview event (Electrobun's preload sends it for Cmd/Ctrl+click on a link) is read from the global `Electrobun.events` emitter, because the typed `BrowserView.on` does not list it; it becomes a `tabOpenRequested` message when `tabUrlOfLink` finds an in-app router URL (`tabs-store.md`).
